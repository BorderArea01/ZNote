# ZNote Pixiv 增强版

基于 [Powerful Pixiv Downloader](https://github.com/xuejianxianzun/PixivBatchDownloader) 19.4.1，保留原抓取、筛选、预览、下载、动图转换、小说与收藏管理，在作品旁和目录抓取入口直接加入 ZNote 入库操作。日常采集无需跳转任务网页。

这是 ZNote 维护的独立增强版，并非原作者官方发行版。上游作者及依赖的署名、许可证保留；增强版和本目录改动按 **GPL-3.0-or-later** 发布。准确上游提交见 [upstream.json](upstream.json)，原许可证见 [LICENSE](LICENSE)。

## 使用

1. 在 ZNote 设置中下载「Pixiv 增强版」，解压后用 Chrome / Edge 的开发者模式加载。停用原版 Powerful Pixiv Downloader，避免两个版本在同一页面重复显示；普通 ZNote 扩展仍可用于其他网站，更新到 0.9.0 后会在 Pixiv 自动让出悬停预览，避免两个预览同时出现。已有原版的设置和下载记录可通过原插件的导出 / 导入功能迁移。
2. 首次打开 Pixiv 左下角「队列 → 连接设置」，填写知识库地址和 ZNote **write** API 令牌，并允许访问所选地址。覆盖同一目录、重新加载增强版即可保留连接，不必重新填令牌；卸载后重装属于新安装。
3. 在 Pixiv 左下角选择目标知识库。鼠标移到作品封面，点击旁边的 **「入库 · Z」** 或按 **Z**，点击按钮后选择「按作品分组」或「逐张入库」，排队保存这部作品的全部原图；快捷键沿用上次选择。小封面也支持；作品详情页另有「本作品入库」。可以连续选择多部作品。
4. 作者、收藏、搜索、排行榜等目录可点击 **「当前范围入库」**；存在多个抓取范围时就地选择。原插件的「开始下载」旁也有「入库」按钮，可直接保存已有结果。即时抓取按钮旁也有对应 **「入库 · …」** 按钮，沿用原插件设置的页数、整目录范围、筛选和排序，不限于当前屏幕上的缩略图。范围设置仍在原插件面板中。无需关闭原插件自动下载：仅明确选择入库的这次结果会转入知识库，普通下载操作保持原行为。
5. **「队列」** 在当前 Pixiv 页面展开，支持附加标签、是否导入 Pixiv 标签、自定义快捷键、进度、停止、继续 / 失败重试。抓取完成且提示「已排队」后，可翻页或关闭来源页；后台继续保存。浏览器完全退出时暂停，重新启动增强版后恢复未完成队列。

「检查结果…」和「详细任务」仍可按需打开独立页面，用于逐项检查与连接管理，不是日常入库的必经步骤。每个文件自动加入作者姓名标签，并保存作品 ID、作者、来源链接、页码、日期及全部标签文本；可索引标签遵守知识库 30 个 / 每个 40 字的限制。

选择「按作品分组」时，每部漫画在知识库中显示为一张带张数的封面，打开按页浏览；整目录会按各作品分别分组。「逐张入库」显示独立图片。知识库的「选择内容」会展开图片组，方便单页整理。重新入库同一作品可以切换展示方式，不重复复制原文件。使用 ZNote 0.9.2 或更新版本。

自动收藏在至少一页成功入库后执行，按采集时的原插件设置和登录账号记录。收藏与入库分别显示进度；失败可在页内队列重试。媒体任务关闭来源页仍继续，收藏同步需要有同一账号的 Pixiv 页面打开，避免切换账号后误收藏。不会把入库伪装成下载成功，也不会改写原下载器的历史记录。

## 能力边界

| 功能 | 原插件下载 | ZNote 入库 |
| --- | --- | --- |
| 插画 / 漫画 | 保留全部原功能 | 整组原文件，无重新编码 |
| 动图 | 保留 GIF / WebM / WebP / APNG / ZIP 等原输出 | APNG，保留解码帧像素与时序；原 ZIP 地址留在备注，ZIP 文件仍由原插件下载 |
| 小说 | 保留 TXT / EPUB / 系列下载 | Markdown 正文、章节、链接、封面和可解析的配图归档；正文原有其他 Pixiv 标记保留，不丢弃文本 |
| 筛选 / 排序 / 多选 | 保留原功能 | 接收最终抓取结果中的文件及页序 |
| 历史 / 重试 | 原下载器独立管理 | 持久任务、暂停后继续、失败重试；按知识库去重 |
| 自动收藏 | 保留原功能 | 沿用原插件「下载后收藏」及附带标签、公开 / 私密设置；入库成功后按作品收藏，失败单独重试 |
| 关注高亮 / 收藏管理 / 定时抓取 | 保留原功能 | 继续使用原插件页面能力；关注关系不自动写入 ZNote，定时下载不会自动变成入库 |

任务存于扩展自己的 IndexedDB。后台文档处理已排队的原图、APNG 和 Markdown；每个任务用浏览器锁防止多个处理器同时入库。最多允许 2000 个未完成任务，保留最近 100 个成功任务，每任务最多 10000 个文件、40 MB 元数据。目录 ID 枚举沿用原插件，在提示已排队前应保留来源页。删除任务记录不会删除知识库资料。目标知识库和标签在开始后固定；未收到上传结果的文件可以重试，服务器按原文件 / 小说来源去重。

静态图片 / 生成的 APNG 单张最多 25 MB。动图源 ZIP 最多 50 MB、500 帧、解码总像素 3200 万，转换超时或超限明确报告失败，仍可使用原插件下载原文件。APNG 是适合知识库展示的派生文件，并非原 ZIP 的字节备份。小说正文最多 40 万字符；归档图片不可访问时保留失败任务供重试。输入 API 令牌只发给配置的知识库服务，不发给 Pixiv 或图片主机，也不写入作品任务元数据。

## 构建与更新

在 ZNote 仓库安装依赖后运行：

```bash
npm run pixiv:build
```

构建从 GitHub 下载固定提交，保留原版静态资源，加入内容脚本、后台队列与 offscreen 文档。只对原版的自动下载准备、下载断点保存及重复抓取确认增加四处显式路由处理：仅跳过已交给知识库的那一份结果数组，主动点击原下载按钮后仍保存原下载断点，不修改原插件持久设置。构建脚本校验补丁位置，上游结构变化时停止构建。发布目录、安装包及完整对应源码包位于 `integrations/pixiv/build/`，不加入 Git。构建只读取固定上游源代码，不包含用户资料。

源码包自带上游 ZIP、本增强版源码及构建脚本：解压后 `npm install`、`npm run pixiv:build` 即可复现。上游更新需要调整提交、版本并重跑回归，不跟随未审查的最新代码自动变化。

网页页面适配由上游实现保留；ZNote 新增流程另做真实扩展到真实 API 的受控集成测试。未对每一个真实账号、搜索条件和上游功能逐项重新验收。
