# 微信收件箱

在 ZNote「设置与连接 → 微信收件箱」选择知识库、填写标签，点击「扫码连接微信」，用手机微信扫码并确认。需要验证码时，在页面填入手机显示的验证码。随后向绑定的微信 ClawBot 会话发送内容。

## 按天收集与手动分篇

默认采用「按天合并」，按消息发送日期、北京时间（Asia/Shanghai）归档。连续发送文字、图片和图片说明，都会按接收顺序追加到同一篇「微信收件 · YYYY-MM-DD」。文字保留 Markdown 与链接，图片下载到本地，笔记配图在素材库折叠为一组；只发图片也会创建带配图的笔记。

| 归档方式 | 何时开始下一篇 |
| --- | --- |
| 按天合并（默认） | 跨天自动分篇，也可手动开始新篇 |
| 手动分篇，持续追加 | 不按日期拆分，直到手动开始新篇 |
| 每条单独保存 | 沿用旧行为：文字为笔记、图片为素材，同条图文组成笔记 |

在微信发送 **`/新篇 主题名`**，或在设置中填入标题后点击「开始新篇」，让后续消息归入新篇。标题可省略；命令必须单独作为一条文字发送，在合并模式下生效。正文中提到这个词不会触发分篇，命令自身不作为笔记正文。设置中的「打开笔记」和收件记录的「查看内容」可直接查看结果。

新篇不立即生成空白笔记，第一条内容到达时才创建。默认知识库、标签、归档方式及目标笔记在收到消息时确定，之后改设置或开始新篇不会把已排队的消息挪到别处。旧版已入库笔记不自动合并；旧版尚未完成的队列仍按原方式处理。

追加时读取笔记最新内容，保留用户修改过的标题、正文、标签和封面顺序。删除、移动当前笔记后，新收到的消息会使用新篇；仍指向旧笔记的排队消息会报错，不复活已删除的内容。打开的编辑器仍使用版本校验，避免旧草稿覆盖新的收件。

一条消息失败时，同篇后续消息等待，其他篇继续处理；重试或忽略失败消息后恢复。失败记录优先显示，避免被后续等待消息挤出最近 30 条列表。单篇最多 50 万字符、30 个标签；达到上限时保留失败消息，整理原笔记后重试，后续内容可另起新篇。

目前不接收群聊、语音、视频及其他文件消息；不支持的消息会在收件记录中显示失败。默认加入「微信」标签；微信聊天图片没有原网页地址，不能凭空补出原作者或来源网址。

微信可能在发送前压缩图片，ZNote 保存的是微信实际提供的字节，不会恢复微信已丢弃的画质。图片仍遵循单张 25 MB 上限，同条消息最多 32 张。GIF 等动画若作为完整图片文件收到，按现有原图存储策略保留。

## 连接方式

### 采集分享链接

在「微信收件箱」开启「采集消息里的链接」并保存后，将小红书、抖音或浏览器的分享链接作为**文字**发送给 ClawBot。服务器会尝试归档正文、配图或视频，原消息仍按原先的按天/手动分篇规则保存，同时附上已归档内容入口。独立归档的正文配图成组，作者名作为标签，来源网址保留。单条消息最多 5 个链接。

默认关闭，只影响启用后接收的消息；不会回头抓取旧聊天。微信名片、小程序卡片及原始视频消息仍不在可接收类型内。网页要求登录、验证或链接失效时保留失败记录，不能把收到链接当作文件已经保存。可在微信收件记录或「网络采集」查看原因并重试；部分图片已保存时按稳定编号复用，避免重试后散成重复图片。

手机不必与电脑处于同一个局域网；电脑必须在线。采集记录与重启状态存于 `settings` 的 `mobile_captures_v1` 中，随完整备份迁移。清理任务记录不会删除已入库内容。

使用腾讯 `openclaw-weixin` 公开的 iLink 通道协议。此实现直接调用该通道，不需要安装 OpenClaw、配置模型，或将 ZNote 暴露到公网。需要微信账号和客户端可使用 ClawBot 入口；真实可用性以手机扫码、绑定后接收测试为准。该入口不会读取普通好友会话和微信历史聊天。

ZNote 电脑保持开机并连接互联网时，通过一个可取消的长轮询连接接收消息；断网后逐步延长重试间隔。连接过期时暂停，提示重新扫码。「暂停接收」保留连接；「断开连接」移除本地连接凭据。收件本身不会自动向微信发送回复。可另外启用下述通知发送能力。

只接收扫码绑定账号发送的消息，过滤其他发送者、机器人消息及群消息。扫码、连接设置、状态和重试接口只允许 ZNote 管理员使用；现有 `read`、`write` API 令牌不能读取微信状态或连接凭据。

## 恢复与备份

游标和接收队列一起持久化，成功后移除队列内的原始消息与图片解密信息。最多保存 100 条未完成消息及最近 400 条已处理记录，设置界面展示最多 30 条，失败项优先。失败项可以重试或忽略；链接过期时可能需要从微信重新发送。停止期间未能从微信接收到的消息受微信平台保留期限约束，不保证无限期补收。

图片使用由账号、发送者、消息编号和图片页序派生的稳定 ID。笔记追加和消息完成回执在同一事务中提交；持久回执只记录消息身份、目标内容 ID 与时间，不保存原始聊天文字或图片密钥。近期记录清理、重复推送和异常重启后，也不会重复追加或恢复已删除内容。不同消息中的相同图片各自保留页位置，但共享原文件。

连接配置、游标和收件记录保存在现有数据库 `settings` 中，主配置键为 `weixin_inbox_v1`，归档目标、已创建笔记标记与完成回执分别使用 `weixin_target_v1:`、`weixin_note_v1:`、`weixin_receipt_v1:` 前缀；未连接时不新增配置。完整备份和恢复包含此配置以及入库原文件，普通内容导出不包含连接信息。迁移时停用旧实例的收件连接后再启用新实例，避免两台电脑使用同一连接竞争收件。

## 通知发送（独立于收件）

在「设置与连接 → 微信收件箱 → 微信通知发送」启用。默认关闭，不自动扫码、不新建收件轮询、不修改原微信绑定、收件开关、知识库或分篇模式。仅向当前绑定的个人微信发送文字，通知不会成为笔记。

启用后，绑定用户需要向原 ClawBot 会话发送一条正常收件消息，以便现有收件连接取得 `context_token`；该消息仍按原规则归档，没有隐藏命令或消息拦截。上下文单独保存，不出现在 API 响应、发送记录或日志中。暂停收件不会清除已有上下文，但暂停期间无法刷新它。

外部服务在 API 令牌区域创建 `notify`（仅通知）令牌。该令牌只能提交通知和查询自己编号对应的发送回执，不能查看笔记、图片、收件记录、其他发送者的记录或修改连接。已有 `read` / `write` 令牌不获得发信权限。

```http
POST /api/weixin/notifications
Authorization: Bearer <仅通知令牌>
Content-Type: application/json

{
  "idempotency_key": "frontdesk-asr-incident-001",
  "title": "前台大屏：语音识别异常",
  "body": "ASR 连接持续失败。建议检查识别服务与网络。"
}
```

`title` 最多 100 字且不能换行，`body` 最多 1500 字；只支持这三个字段，不允许传入接收人、微信凭据、附件或任意微信 API 地址。调用方应只提交脱敏诊断，不能发送访客姓名、人脸、录音、原始业务日志或密钥。

- `200 / accepted`：微信接口已接受，不代表手机已展示或用户已读。
- `202 / sending`：同一编号的原请求仍在执行，查询其回执即可。
- `409`：未启用、未绑定、缺上下文，或同一编号用于不同内容；本次没有发送。
- `429`：通道繁忙、3 秒发送间隔或有效回执容量达到上限；本次没有发送，可退避后以同一编号重试。
- `502 / rejected`：微信业务接口拒绝；不会暂停或断开原收件服务。
- `504 / unknown`：超时、HTTP 错误或未取得明确接受结果，无法确认微信是否已经收到，不自动重发。

`GET /api/weixin/notifications/:key` 读取当前令牌的回执。编号在同一令牌下 30 天内去重；管理员会话共享管理员编号空间。最多保存 1000 条有效回执，到达上限拒绝新请求而非提前删除有效记录。回执不保存通知正文，只保存内容校验值、编号、时间与固定说明；恢复备份会恢复当时回执，备份之后已发送的消息不能据此推断未发送。

发送前持久化意图，崩溃后未完成的请求显示 `unknown`，不会开机补发。被微信拒绝或结果未知的编号仍占用去重记录，不以相同编号自动再发；确认处理后若确实需要重新通知，由管理员/调用服务明确创建新的事件编号。通知开关关闭后不接受新发送，已发出的 HTTP 请求无法撤回。

微信可能拒绝过期的会话上下文；不假定固定有效期，也不通过额外轮询或重新绑定绕过限制。`-2` 返回会提示更新上下文，但它本身不能证明具体失效原因。长期无人交互的主动通知送达仍需真实运行验证。没有接通各终端上报前，此功能只是发信通道，不能宣称已经订阅全部设备。

配置、上下文和回执使用独立 `settings` 键：`weixin_notifications_v1`、`weixin_notification_context_v1`、`weixin_notification_receipts_v1`。完整备份包含这些键，普通内容导出不包含它们。没有更改数据库表结构或现有收件主键。

**回退到不认识 `notify` 权限的旧版 ZNote 前，必须先撤销全部仅通知令牌。** 旧版对未知权限可能按一般 API 令牌处理，不能带着新令牌直接回退旧代码。停用发送可直接关闭独立通知开关，不必停止收件或回退程序。

## 协议依据与许可

参考 [Tencent/openclaw-weixin](https://github.com/Tencent/openclaw-weixin)，核对提交 `7c04adc3e95775efd661ab9fba0626d86d237713` 的 [协议说明](https://github.com/Tencent/openclaw-weixin/blob/7c04adc3e95775efd661ab9fba0626d86d237713/docs/protocol.md)、二维码登录、HTTP 请求和 CDN 解密实现。腾讯说明中的类型字段并不等于完整的服务端契约，后续接口变化需继续以真实登录和收件验证。

协议实现和媒体密钥解码参考腾讯 MIT 代码，许可保存在 [TENCENT-LICENSE](TENCENT-LICENSE)。二维码在浏览器内由 MIT 许可的 [node-qrcode](https://github.com/soldair/node-qrcode) 生成，不向第三方二维码服务发送登录内容。
