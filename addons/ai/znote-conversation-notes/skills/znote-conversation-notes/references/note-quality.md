# 学习笔记质量标准

## 应保留的内容

- **结论及其成立条件**：读者能分辨结论适用于什么范围。
- **推理和纠错**：保留导致最终结论的关键证据，以及错误方案为什么被放弃。
- **可复用方法**：把只适用于本次对话的操作，提炼为可再次执行的步骤。
- **原始出处**：保留重要链接、论文、文档、代码和数据来源；链接文字应说明内容，而非只写“来源”。
- **不确定性**：没有验证的内容放入“待验证”，不要用肯定语气补全空白。

## 应删除的内容

- 寒暄、致歉、确认收到、工具运行过程和与学习主题无关的项目状态。
- 已被后续答案完全取代的重复说明。
- 没有解释价值的逐句问答记录。
- 仅用于当时沟通的敏感信息，包括令牌、密码、Cookie、个人路径和内部地址。

## 推荐表达

根据内容增删小节，避免每篇都长得一样。技术主题可以使用：

```markdown
# 具体标题

> 一句话说明这篇笔记解决什么问题，以及核心结论。

## 问题背景
## 核心结论
## 原理与推理
## 实践步骤
## 易错点与边界
## 待验证
## 复习问题
```

概念解释适合“定义 → 直觉 → 例子 → 反例 → 应用”；方案讨论适合“目标 → 约束 → 选项对比 → 决策 → 验证”。短对话不必凑齐所有小节。

图片紧跟首次引用它的段落。替代文本描述图中有助于理解的内容，例如 `![请求队列从接收、重试到完成的状态转换](...)`，不要只写“截图”。
