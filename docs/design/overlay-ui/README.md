# 采集浮窗交互提案

用户收窄需求：手机 App 主界面暂时不改，只把展开与收起的浮窗做成熟；先给四版选择，不直接替换 Android 实现。本提案与上一轮整套手机主题分开，A/B/C/D 编号只指本目录。

| 编号 | 形态 | 展开方式 | 取舍 |
| --- | --- | --- | --- |
| A 磁吸豆 | 9×34 dp 细豆 → 40 dp 圆钮 | 轻量卡片 | 兼顾入口辨识与少遮挡 |
| B 折页签 | 15×38 dp 页签 → 40 dp 圆角方钮 | 书签卡片 | 入口明显，连续采集易找 |
| C 轻胶囊 | 16×30 dp 圆弧 → 42 dp 圆钮 | 横向双操作胶囊 | 延续现有圆形，展开更矮 |
| D 侧边轨 | 4×44 dp 线条 → 40 dp 圆角方钮 | 窄侧抽屉 | 收起最隐蔽，首次发现较弱 |

所有方案共用现有深蓝色方向与手写 Z，不靠换色制造四版。拖离边界立即恢复完整形状，松手吸向近侧；取消拖动不触发打开，键盘方向键可换侧/移位。贴边视觉小，但演示中的触区为边缘 24×48 CSS 像素，避免大透明热区占据作品；原生实施须结合系统手势边缘与真实机型调整，不能把网页尺寸直接当成已验证的 dp。

采集自动收起；环线只表示正在处理，不编造下载百分比。成功显示同一线条体系的图标与“已存入 · 知识库”，短时提示收回后留下点标记；失败保留标记与重试入口，不自动展开。记忆选库、浮窗内粘贴、前往知识库均保留。所有结果是模拟，不读取剪贴板、不联网采集、不调用库 API；原生实现尚未改变，不能称已修复手机问题。

公开交互预览：<https://znote-capture-inbox.pages.dev/design/overlay-ui/>。`?plan=bean|bookmark|pebble|rail` 直达单版；`?board=1` 为宽屏四版比较视图。源码只包含三个公开静态文件，Pages 的复制白名单不包含本说明或用户数据。

参考 Android 官方[触摸事件与取消处理](https://developer.android.com/develop/ui/views/touch-and-input/gestures/viewgroup)的思路区分点击/拖动/取消。官方[通知气泡](https://developer.android.com/develop/ui/compose/notifications/bubbles)面向对话，不把其 API 套用为采集浮窗；沿用现有采集服务架构。界面及交互原创，没有引入第三方组件或新权限。

定向验收：`tests/overlay-design-preview.mjs`，通过资源守卫串行检查鼠标和模拟触屏、四种形态、拖动中恢复完整按钮、左右吸边、取消、结果短提示和失败恢复、粘贴校验、选库、关闭、键盘与320px窄屏。`--live` 对照真实发布的三个静态文件。截图与浏览器检查不代表荣耀真机已验收。
