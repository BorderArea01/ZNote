# 角色设定集布局提案与选型

用户要求先给多版角色卡与分栏布局，随后明确选择“第一第二种都不错，可以都采纳，然后可切换”。正式私人插件1.2.0采用 A 分区画廊与 B 角色档案，在工作台顶部切换；C、D仅保留为独立演示方案。

两种正式视图共享角色、分栏、排序、素材引用和保存逻辑，不重新导入或复制资源；切换保留作品、搜索、分栏筛选和当前角色。视图偏好按知识库在当前浏览器记忆，角色焦点按知识库和作品记忆。手机档案视图先显示角色列表，点入档案后可返回；上传或关系编辑未结束时暂停切换，避免丢失操作。知识库启停与原有12张卡的归属保持。

| 方案 | 布局 | 适用场景 | 取舍 |
| --- | --- | --- | --- |
| A 分区画廊 | 阵营纵向分区，角色卡网格铺满宽度 | 以浏览形象、查找角色为主 | 阵营多时纵向浏览，可按阵营筛选 |
| B 角色档案 | 阵营目录、角色列表、就地档案三栏 | 连续写设定与查素材 | 封面展示较克制；手机先选角色再看档案 |
| C 阵营看板 | 横向阵营列、较矮的横卡 | 同时比较人物阵营与定位 | 多列时横向滚动，手机可筛选阵营 |
| D 世界索引 | 阵营分组的行列表，选择后出现批量工具 | 角色多、检索和整理频繁 | 以管理效率为主，封面较小 |

统一使用中性灰阶和同一组12位虚构角色；原创SVG灰色人像为封面占位，不是替换用户图片的图标方案。预览支持切换阵营、搜索及空结果恢复、分组收起、打开/关闭档案、档案内容切换与示例多选。新建/阵营管理只显示演示提示，不假称保存真实内容。倾向选择只存在当前浏览器，不自动提交给聊天或应用。

公开预览：[四版交互](https://znote-capture-inbox.pages.dev/design/character-layouts/)、[四版总览](https://znote-capture-inbox.pages.dev/design/character-layouts/?board=1)。单版用 `?plan=a` / `b` / `c` / `d`，`&solo=1`用于紧凑预览与截图。这些是虚构资料演示；正式双视图在本机已挂载角色插件的知识库中使用。

源码、构建与验收集中在被 Git 忽略的 `plugins/character-studio/design/`，正式插件manifest不加载这份演示。192MiB受控入口执行 `build.mjs` 生成 dist 的 index.html、ui.css、ui.js；Pages打包仅白名单复制这三份虚构数据的演示资产，不包含私人插件实现、资料、源码映射或凭据。没有本地源码时跳过该可选预览，现有手机邀请、下载与其他设计预览保持。

`verify.mjs` 使用临时本地静态服务，`--live`核对真实公开路径及全部三文件字节。桌面/390px模拟触屏覆盖四版、搜索/空结果恢复、阵营切换、收起、档案/关系/素材、关闭、示例多选、倾向选择保持、帮助、320px边界及减少动画；要求零知识库API请求。

正式实现由私人目录的`verify-views.mjs`在当前3741实例验证双视图共享编辑、筛选与焦点保持、重开记忆、图组引用及原件返回、附件、关系、草稿、409/503恢复和小屏；`verify-ui.mjs --live`回归完整画廊工作流与排序；`verify-existing-views.mjs`只读检查用户现有12张卡、键盘外框、短窗口和320/390px触屏边界，核对资料与PIN未变。插件本体继续Git忽略，不能强制加入公开仓库。浏览器模拟不代表荣耀真机验收。
