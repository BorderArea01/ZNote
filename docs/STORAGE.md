# 存储、导出与恢复

[返回首页](../README.md)

## 文件如何保存

```text
data/
├── znote.sqlite         内容、知识库、标签、鉴权散列、事件与订阅
├── znote.sqlite-wal     运行期间可能存在的 SQLite 日志
├── znote.sqlite-shm     运行期间可能存在的 SQLite 共享内存文件
├── media/              原图、无损 Gzip 原图、原始视频
├── uploads/            上传和合并的临时文件
├── imports/            平台采集任务的临时下载
├── backups/            完整备份与调度策略
└── restore-staging/    已校验的恢复预览
```

SQLite 保存元数据，媒体文件按不可变原文件管理。一个数据目录只能由一个 ZNote 实例管理。

图片计算 SHA-256 后去重，仅在 Gzip 更小时使用无损封装。读取原图或导出时解压，返回与最初上传逐字节一致的内容，包括像素、EXIF 和动画。视频原文件不进行有损转码。

同库重复文件复用条目；跨库可以有各自的标题、说明、标签和收藏，但共享同一物理文件。网络重复采集会补充来源链接与网站标签，不覆盖原备注。

漫画中的不同页，以及不同笔记使用的相同图片，可以拥有各自的条目、分组与页序，底层仍共享原文件。笔记配图组以 `note:笔记ID` 标识；保存笔记时按正文顺序整理，删除正文引用只解除分组，不删除素材。移动笔记或整组时，所属笔记与配图一起移动，冲突时在同一事务中全部回滚。

0.9.6 增量加入 `group_order` 保存手动展示顺序，第一张为封面；来源页码 `group_index` 保留用于重复采集识别。旧数据的展示顺序为空时沿用原始页序，不改写媒体文件。完整备份包含排序；恢复此版本备份需使用 0.9.6 或更新的兼容版本。笔记排序可选择仅调整素材组，之后仅修改标题、标签等不会重置顺序；正文配图发生增删或换序时，按新的正文顺序整理。

0.9.3 首次启动会自动整理现有笔记的本地配图；共用图片仅增加必要的元数据记录并调整本地引用，不复制或改写原图。完整备份保存组标识、页序和笔记链接。恢复 0.9.3 之前的完整备份后重启服务，即可执行这次整理。

图片缩略图和视频首帧封面均按需生成，使用有上限的内存缓存，不长期写入磁盘。视频解码仅读取本地原文件，单次最多处理一帧、最长 15 秒，并与图片缩略图共用受限队列。封面失败不影响原视频播放、下载或备份。数据库、日志和备份仍有额外空间开销，因此不能保证每个库的总占用都比直接保存原文件更小。网页设置中的存储统计显示实际占用和节省量。

### 删除图片与笔记引用

「删除」先移入回收站，可恢复。若笔记正在使用该图片，删除事务会为笔记建立独立配图条目并改写 Markdown 内部链接，保留画质、说明和分组顺序；多个条目共享同一份原文件，不复制图片字节。包括回收站内的笔记也不会引用回收站图片。新建、编辑笔记引用已删除条目会返回 409，须先恢复；启动升级与完整备份恢复会修复历史引用。

回收站提供单项、所选和清空当前知识库的永久删除。清空覆盖该库全部回收站内容，不受搜索和分页限制。确认后删除条目无法从回收站恢复，已有备份不受影响。仍被其他条目或独立配图使用的原文件保留；最后一个引用消失后才释放文件。因此移入回收站不会立即释放空间，保留笔记配图的永久删除也可能释放 0 B。

schema 7 使用持久文件清理队列：条目删除与队列登记在同一 SQLite 事务中提交，再清理原文件和旧版缩略图。清理失败自动每分钟重试，服务重启继续执行；重试前再次检查引用。备份、导出、上传与物理删除通过维护锁协调，避免读写中的文件被删除。备份不导入旧的待清理任务。

schema 8 新增 `undo_actions`：与内容修改在同一事务内保存压缩后的字段差异，不复制原文件。按会话保留 24 小时、最多 50 条、压缩总量不超过 32 MB；已撤销记录立即释放差异正文。撤销记录不会阻止永久删除原文件。完整备份包含数据库，但恢复时清空旧撤销记录，避免将恢复前的操作应用到恢复后的数据。


## 笔记草稿与历史

schema 9 新增 `note_versions`，保存已提交笔记的标题、Markdown 正文和标签，使用 Gzip 压缩；每篇保留最近 50 个版本、压缩总量不超过 8 MiB。升级时将已有笔记当前内容作为首个版本，不改写原正文。历史随完整备份与目录迁移保留；恢复 schema 9 备份需要 0.9.16 或更新的兼容版本。

历史正文中的图片链接不会额外固定原文件，也不复制图片。选择版本仅将文字载入编辑器；保存时重新验证图片引用，已移入回收站或永久删除的图片不能被旧正文重新引用。普通删除笔记保留历史，永久删除笔记一并清理。

浏览器本地草稿使用 IndexedDB，并在离开页面时尝试写入应急副本。各窗口使用独立草稿 ID；本地容量不足会显示失败状态，仍可提交到服务器或导出当前 Markdown。草稿和编辑位置只属于当前浏览器及访问地址，不在服务器 `data/` 中，不随完整备份迁移；清除站点数据会删除这些草稿。知识库删除后，遗留本地草稿可从「未分类」继续找回。

## 常用筛选的存储

schema 10 增加 `saved_views`，仅保存名称、所属知识库、筛选配置和修改版本，不复制任何媒体或搜索结果。每库最多 50 个，同库名称唯一；未分类使用独立的名称约束。删除知识库时一起清理其筛选，原有内容仍按既有规则移入未分类。

定义保存在服务器，其他设备登录同一实例后可读取，并随完整备份与目录迁移保留。恢复 schema 10 备份需要 0.9.17 或更新的兼容版本。恢复没有常用筛选的旧备份时，会清空当前定义，避免留下与旧数据不对应的配置。

## 浏览位置的存储

schema 12 增加 `reading_progress`，每个知识库一条版本化记录，内部最多 20 个图片组 / 单图位置；只存图片 ID、分组标识和时间。位置不固定或复制原文件，清除记录不影响内容。失效的条目读取时隐藏，下一次写入时清理；删除知识库会一起清理其记录。

完整备份包含浏览位置；恢复 schema 12 备份需使用 0.9.20 或更新兼容版本。恢复时生成新的 `reading_epoch`，使恢复前的待同步请求失效。未同步位置在当前浏览器本地暂存，最多保留 32 个知识库，不含正文或令牌；它们不包含在服务器备份中。清除浏览器数据会移除这些尚未同步的位置。

## 手工分组的存储

schema 11 增加 `items.group_manual` 和 `group_origin_id`，分别标记手工整理、素材引用的来源记录。`group_index` 保留来源页码用于去重，`group_order` 决定展示顺序及封面。重复采集不覆盖手工分组或主动拆散的结果；新采集的其他页仍按其来源组入库。

笔记配图整理为素材组时保留原组与正文，仅增加共享同一原文件的元数据记录；删除文件仍检查全部有效引用。分组元数据随完整备份迁移，恢复 schema 11 备份需使用 0.9.18 或更新兼容版本。

`group_operations` 与整理事务一起保存压缩回执，24 小时内同一调用者重试同一请求不会重复创建引用。每个调用者压缩回执上限 32 MiB，达到限制时本次事务回滚；下次提交时清理过期回执。完整恢复清空旧回执和撤销记录，避免套用到恢复后的数据。预览和响应有大小限制，不复制原文件。

## 六种导出

| 模式 | API 参数 | 包含内容 |
| --- | --- | --- |
| 资料包 | `portable` | Markdown、解压后的原媒体、元数据清单 |
| 图片包 | `images` | 原图、标题、说明与标签信息 |
| Markdown | `markdown` | 图文笔记及引用的附件，相对图片链接 |
| JSON | `json` | 正文与元数据，不含媒体二进制 |
| 离线网页 | `html` | HTML、配图和浏览器可播放的视频 |
| 完整备份 | `backup` | 一致性数据库快照和全部引用的媒体 |

普通导出可指定知识库和是否包含回收站；完整备份始终包含全部知识库与回收站。文件名按知识库和可读标题组织，添加短 ID 避免重名；`layout=legacy` 可使用旧路径布局。

资料包、Markdown 和 JSON 适合阅读或二次处理，不能替代完整实例恢复。恢复实例请使用完整备份。

## 自动备份与网页恢复

在设置中配置自动备份周期与保留份数，也可立即备份。恢复时先上传完整 ZIP，检查预览中的数量和元数据，再执行恢复。服务会先保存当前状态的安全备份；失败时回滚，成功后重新登录。

仅管理员浏览器会话可生成、下载或恢复完整备份，普通 read/write API 令牌没有此权限。

默认完整备份 ZIP 上限 5 GiB、解压容量上限 20 GiB，恢复前还需要为安全备份和暂存文件留出空间。备份目录在服务数据目录中，建议另外复制一份到独立磁盘或备份位置。

## 整目录迁移

1. 停止旧服务。
2. 完整复制 `data/`，包括当时存在的 SQLite 日志文件。
3. 在目标机器安装相同或兼容版本，指向复制的数据目录。
4. 启动后检查知识库、笔记、原文件和来源链接。

不要仅在运行中复制 `znote.sqlite`；使用网页的一致性完整备份，或停服后复制整个目录。

正常上传/合并失败会清理相关临时文件；强制终止或断电可能留下暂存或未关联文件。不要依据文件名自行删除媒体文件，避免破坏共享引用。

永久删除笔记时，保留的配图会转成普通图片组（album:笔记 ID），保留组名、group_index 与 group_order。删除笔记本身不会打散图集。0.9.8 已发生的分组丢失可通过 scripts/repair-detached-note-groups.mjs 对照删除前的数据库备份定向修复；默认只预览，实际应用须先停止服务并备份当前完整数据。无法从备份可靠确认或已再次修改的分组会停止修复，避免猜测覆盖。
