# 存储、导出与恢复

[返回首页](../README.md)

## 文件如何保存

```text
data/
├── znote.sqlite         内容、知识库、标签、鉴权散列、事件与订阅
├── znote.sqlite-wal     运行期间可能存在的 SQLite 日志
├── znote.sqlite-shm     运行期间可能存在的 SQLite 共享内存文件
├── media/              原图、无损 Gzip 原图、原始视频
├── uploads/            上传和合并的临时文件
├── imports/            平台采集任务的临时下载
├── backups/            完整备份与调度策略
└── restore-staging/    已校验的恢复预览
```

SQLite 保存元数据，媒体文件按不可变原文件管理。一个数据目录只能由一个 ZNote 实例管理。

图片计算 SHA-256 后去重，仅在 Gzip 更小时使用无损封装。读取原图或导出时解压，返回与最初上传逐字节一致的内容，包括像素、EXIF 和动画。视频原文件不进行有损转码。

同库重复文件复用条目；跨库可以有各自的标题、说明、标签和收藏，但共享同一物理文件。网络重复采集会补充来源链接与网站标签，不覆盖原备注。

缩略图按需生成，使用有上限的内存缓存，不长期写入磁盘。数据库、日志和备份仍有额外空间开销，因此不能保证每个库的总占用都比直接保存原文件更小。网页设置中的存储统计显示实际占用和节省量。

## 六种导出

| 模式 | API 参数 | 包含内容 |
| --- | --- | --- |
| 资料包 | `portable` | Markdown、解压后的原媒体、元数据清单 |
| 图片包 | `images` | 原图、标题、说明与标签信息 |
| Markdown | `markdown` | 图文笔记及引用的附件，相对图片链接 |
| JSON | `json` | 正文与元数据，不含媒体二进制 |
| 离线网页 | `html` | HTML、配图和浏览器可播放的视频 |
| 完整备份 | `backup` | 一致性数据库快照和全部引用的媒体 |

普通导出可指定知识库和是否包含回收站；完整备份始终包含全部知识库与回收站。文件名按知识库和可读标题组织，添加短 ID 避免重名；`layout=legacy` 可使用旧路径布局。

资料包、Markdown 和 JSON 适合阅读或二次处理，不能替代完整实例恢复。恢复实例请使用完整备份。

## 自动备份与网页恢复

在设置中配置自动备份周期与保留份数，也可立即备份。恢复时先上传完整 ZIP，检查预览中的数量和元数据，再执行恢复。服务会先保存当前状态的安全备份；失败时回滚，成功后重新登录。

仅管理员浏览器会话可生成、下载或恢复完整备份，普通 read/write API 令牌没有此权限。

默认完整备份 ZIP 上限 5 GiB、解压容量上限 20 GiB，恢复前还需要为安全备份和暂存文件留出空间。备份目录在服务数据目录中，建议另外复制一份到独立磁盘或备份位置。

## 整目录迁移

1. 停止旧服务。
2. 完整复制 `data/`，包括当时存在的 SQLite 日志文件。
3. 在目标机器安装相同或兼容版本，指向复制的数据目录。
4. 启动后检查知识库、笔记、原文件和来源链接。

不要仅在运行中复制 `znote.sqlite`；使用网页的一致性完整备份，或停服后复制整个目录。

正常上传/合并失败会清理相关临时文件；强制终止或断电可能留下暂存或未关联文件。不要依据文件名自行删除媒体文件，避免破坏共享引用。
